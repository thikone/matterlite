# M4 progress

M4 (MatterLite.md §18), threads and reactions: post actions with edit and delete, reactions
with an emoji picker, reply threads in the **right panel** (and "Open in tab"), edit history
in the right panel, the **Activity** tab (Threads, Mentions, Saved, Drafts, Scheduled), and
History's server-side search pass.

The protocol pieces mostly exist from M1–M2: `mm_store` applies `post_edited`,
`post_deleted`, `reaction_*` and `thread_*` events, keeps thread timelines and followed-thread
state, and has `has_channel_permission`; the engine loads threads (`Command::OpenThread`,
the P3 followed-threads sync). M4 adds the writing requests, the views and the engine
commands that tie them together.

## Steps

1. **Post actions** — *done (below)*. On hover, a post shows a small toolbar at its top
   right (Warp-style icon buttons; More now, React and Reply come with steps 3 and 4). More,
   or a right-click on the post, opens the post menu: Follow/Unfollow thread (CRT), Mark as
   unread, Save/Unsave, Pin/Unpin, Copy link, Copy text, Delete (Reply and Edit join with
   their steps). Entries follow the permissions (`delete_post`, `delete_others_posts`;
   `edit_post`, `edit_others_posts` and the `PostEditTimeLimit` for step 2), and nothing that
   writes shows in archived channels or on pending, system or deleted posts. `mm_api` and
   engine commands for pin, save (`flagged_post` preference), mark unread, follow and
   delete; pin and save show at once and are undone with an error when the request fails.
   Delete asks first (a root post: "and its N replies") and sends `DELETE /posts/{id}`.
2. **Edit** — *done (below)*. Edit opens an inline editor in place of the message (Enter saves,
   Shift+Enter newline, Esc cancels; saving empty text asks to delete), and `↑` in an empty
   composer edits my last post in the chat (§13). `PUT /posts/{id}/patch`; the timeline
   keeps its position while the editor is open.
3. **Reactions** — *done (below)*. Click a reaction chip to add or remove mine; hovering a
   chip lists who reacted; a `+` chip and React in the toolbar open the **emoji picker**
   (search by name as the webapp's, categories from the emoji index, custom emoji, recently
   used first from the `recent_emojis` preference, as the webapp keeps it). `POST /reactions`,
   `DELETE /users/{uid}/posts/{pid}/reactions/{name}`; the server's limit on distinct emoji
   per post (`UniqueEmojiReactionLimitPerPost`) is shown instead of failing silently.
4. **Threads in the right panel** — *done (below)*. The reply count, Reply, "replied in a thread" and a reply
   shown in the channel (CRT off) open the thread in the right panel: the root post and its
   replies drawn with the chat's rows and actions, a composer that replies (`root_id`, its
   own draft per thread), loaded with `OpenThread` and live. Header: channel name, Follow or
   Unfollow, Open in tab, close (`Esc`). Viewing a followed thread marks it read under CRT
   (`PUT /users/{uid}/teams/{tid}/threads/{id}/read/{ts}`). The panel's open thread and width
   are saved per account.
5. **Thread tabs** — *done (below)*. "Open in tab" turns the thread into a chat tab (§10.7): a tab holds a
   chat or a thread, labelled with the thread icon and the root's excerpt, with the same
   focus-or-open, LRU, pin, close/reopen and persistence (tab lists saved by M3 still load).
6. **Edit history** — *done (below)*. "(edited)" on my post shows its earlier versions in
   the right panel (`GET /posts/{id}/edit_history`, current version first), each rendered as
   a message with its time; my own post can be restored to an earlier version. (The webapp
   has no post-menu entry for it; the server gives the history to the author only.)
7. **Activity tab** — *done (below)*. Sub-tabs, each a list whose rows open the post (chat tab plus flash,
   or the thread in the right panel):
   - **Threads**: followed threads of the selected team, unread first, with unread and
     mention counts, participants and the last reply; Mark all read; under CRT only.
   - **Mentions**: the server search for my mention keys (the webapp's recent mentions).
   - **Saved**: `GET /users/{uid}/posts/flagged`, live with the `flagged_post` preferences.
   - **Drafts**: the unsent drafts in the cache (channel and thread composers), with Delete.
   - **Scheduled**: `GET /posts/scheduled/team/{tid}` with their times; Delete.
   The toolbelt's Activity icon shows the unread thread and mention counts.
8. **History server-side search** — *done (below)*. "Search older on server" (and automatically when the
   query reaches past the local history): `POST /teams/{tid}/posts/search` with
   `in:<channel>` (`in:@user` for DMs), results merged into their date groups and marked
   "from server", their posts cached. Unavailable with regex or case-sensitive matching,
   and the pane says so (§10.8).
9. **Acceptance** — the M4 checks against the test server (two clients: MatterLite and the
   webapp), docs, CI, the VM build.
