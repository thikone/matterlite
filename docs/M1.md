# M1 progress

M1 (MatterLite.md §18): `mm_model`, `mm_api` (login + MFA, bootstrap endpoints), `mm_ws` (auth,
seq, resume, backoff); a CLI test harness prints events.

## Done

- [x] `mm_model`: serde types for the wire format of `server/public/model` — `User`, `Status`,
      `Team`, `TeamMember`, `TeamUnread`, `Channel` (+ `ChannelType`), `ChannelMember`,
      `SidebarCategory`, `Post`, `PostMetadata`, `PostList`, `Reaction`, `FileInfo`, `Emoji`,
      `ThreadResponse`/`ThreadList`, `Preference`, `Role`, `AppError`, `ClientConfig` (flat
      string map with typed accessors and the CRT rule), typed ids (`UserId`, `ChannelId`, ...),
      `SessionToken` (never shown by `Debug`/`Display`). Tolerant everywhere: missing fields
      default, unknown fields are ignored, `null` lists and maps read as empty.
- [x] `mm_model::ws`: frame parsing (events vs responses), `Broadcast`, `ClientAction` frames
      (challenge, ping, typing, presence, active status, statuses) and `WsEvent::decode` for
      about 45 events, with the second JSON parse of string-encoded fields (`post`,
      `channelMember`, `preferences`, `updatedCategories`, ...). Unknown events are
      `WsEvent::Unknown(name)`; a payload missing its entity is a `DecodeError`.
- [x] `mm_api::Client`: `X-Requested-With` + Bearer on every request, no cookies; `AppError`
      bodies (`Unauthorized` for 401), `RateLimited { retry_after }` for 429 (plain-text body,
      `Retry-After` / `X-RateLimit-Reset`), `Status` for non-JSON errors, `Decode`; the server
      version from `X-Version-Id`. `ServerUrl` handles sub-paths, missing schemes and the
      WebSocket URL (`WebsocketURL` override).
      Endpoints: ping, client config/license, login (token from the `Token` header; MFA via
      `ApiError::needs_mfa_code` and a retry with the code), logout, me, preferences, teams, team
      members, team unreads, roles by names, my channels, all channel memberships (NDJSON or
      array), sidebar categories, view channel, channel posts (page/before/after/since, CRT),
      posts around the first unread, users by ids, statuses by ids.
- [x] `mm_ws`: a Tokio task per server with `WsHandle` (send, reconnect now, close) and an
      ordered `WsOutput` stream. Bearer header on the upgrade plus the authentication challenge,
      `seq` checking with 4001 + resume (`connection_id`, `sequence_number`,
      `disconnect_err_code`), `MissedEvents` when the server answers a resume with a new
      connection id, ping every 30 s with 4000 on timeout, the webapp's backoff, graceful close,
      TLS with the OS certificate store (`rustls-platform-verifier`), `ResumeState` to resume
      after an app restart (M2).
- [x] `mm-cli` harness (`cargo run -p mm_cli -- <server-url> <ping|bootstrap|events>`):
      `ping` (version, site URL, sign-in options), `bootstrap` (the WebApp.md §6 startup: teams,
      channels with unread/mention counts under the CRT rule, DM partners and statuses, sidebar
      categories, roles, per-step timings), `events` (connects and prints every event until
      Ctrl+C). `MM_TOKEN`, or a password login with MFA prompt; it logs out sessions it created.
- [x] Tests: 19 `mm_model` (fixtures in `crates/mm_model/fixtures`, hand-written from the Go
      structs), 11 `mm_api` against `wiremock`, 13 `mm_ws` against a scripted tokio-tungstenite
      server (gap → resume and replay, new connection id → missed events, ping timeout, 401,
      unconfirmed sessions, backoff, reconnect now).

## Checked against a real server

Against community.mattermost.com (server 12.2, no account): ping, client config, the
session-expired `AppError` for an invalid token, and `wss://` with the OS certificate store.

That run found that **an invalid token does not fail the WebSocket upgrade**: the server answers
`101` and drops the socket once the challenge fails. `mm_ws` therefore reports
`session_confirmed: false` for connections that end before a ping reply or event, and those count
as failures for the backoff (WebApp.md §7.2 documents this and the other resume details).

## Known issues

- Not all events decode yet: `scheduled_post_*`, `channel_bookmark_*`, `draft_*`,
  `post_acknowledgement_*`, `open_dialog` and plugin events are `WsEvent::Unknown` until the
  milestones that need them.
- `mm-cli` is a developer tool: it prints all channels, without paging, and user ids instead of
  names outside of DMs.
